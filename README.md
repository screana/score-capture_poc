# score-capture_poc

カラオケの採点画面（DAM / JOYSOUND）を撮るだけで、点数や日付を自動で記録できるようにするための試作です。
カラオケ記録アプリ（曲ごとの点数・キー・機種・録音を残す）の、入力の手間を減らす部分にあたります。

- `index.html` … スマホで採点画面を自動撮影するページ（GitHub Pages で公開）
- `poc/ocr/` … 撮った写真から点数などを読み取る OCR の試作（Python）
- `poc/collect/` … ネットから採点画面の画像を集めるための道具

公開ページ: https://screana.github.io/score-capture_poc/
（Settings → Pages で `main` / `/(root)` を有効にしたとき）

## 現状（2026-10-08 時点）

### 自動撮影ページ `index.html`
カメラ映像を 10fps ほどで解析し、次の 3 条件がそろった瞬間に連写して、一番くっきりした 1 枚を
1600×900 の正面向きに補正して残す。処理はすべて端末内で、外部ライブラリなし。

| 条件 | 判定方法 |
|---|---|
| 画面の四隅が見つかって止まっている | 明るさのしきい値を 4 段階で変え、テレビの黒い縁に囲まれた明るい領域を連結成分で探す。凸包から最大面積の四角形を取り、四角形らしさ×面積でスコア付け。直近 5 フレームの四隅の移動量で静止を判定 |
| くっきりしている | 四隅の内側でラプラシアンの分散を計算し、直近 2 秒の最大値の 85% 以上かつ下限以上 |
| 手が揺れていない | `DeviceMotion` の回転速度（°/秒）。センサーがなければ無視 |

- 撮影後は同じ画面を何度も撮らないよう一時停止する（「次を撮る」で再開）
- 「写真で試す」で既存の写真にも同じ処理（検出→補正）をかけられる
- 「調整」から、くっきり度の下限・比率・揺れの上限・静止時間・連写枚数を変えられる（`localStorage` に保存）
- カメラは https か localhost でしか動かない。Claude のプレビューやアプリ内ブラウザでは開けない

ヘッドレス Chromium に「前半は揺れてブレる、後半は静止」の偽カメラ映像を流し、
揺れている間は撮らず、静止後に自動撮影して補正されることを確認済み（くっきり度はブレ中 ≈800、静止後 ≈4100）。
実機でも動作確認済み。

### OCR 試作 `poc/ocr/`
手元の写真 13 枚（JOYSOUND 7 / DAM 6）で **136 項目中 133 項目（97.8%）** を正しく読めた。
ただし、ルールはこの 13 枚を見ながら調整したので、新しい写真では下がる前提。
調整に使っていない写真 1 枚（DAM・手ブレあり）では、総合得点・全国平均・機種は正解、日付とボーナスはブレで読めなかった。

読めなかった項目は「空欄」になり、間違った値が入らないようにしてある（検算・照合で弾く）。

| 項目 | 結果 | 方法 |
|---|---|---|
| 機種・採点モード | 13/13 | OCR の文字（「分析採点」「/40」「ハートボーナス」「月次」「Ai感性」など）で判定 |
| JOYSOUND の内訳 5 項目・AI ボーナス | 全問正解 | `xx.xxx/40` などの形で正規表現 |
| JOYSOUND の総合得点 | 7/7 | **内訳 5 項目 + AI ボーナス = 総合得点** で計算し、画面の小数部と照合（全 7 枚で成立） |
| DAM の総合得点 | 6/6 | 下記の工夫。1 枚は誤読（97.334）を最高点との矛盾で検出して補正 |
| 日付・全国平均・前回・最高・月次ランキング | 全問正解 | 正規表現＋ラベルの近くの数字を探す |
| テクニック回数 | 5/6 | 外れた 1 枚は画面切り替え中の写真（空欄で返した） |
| 曲名・歌手名 | ほぼ全滅 | 中国語用の OCR モデルがカナに弱い。未対応 |

**DAM の総合得点の読み方**（`dam_total.py`）
1. 毎回確実に読める小さな「全国平均」の文字を目印にして、その上を数字の帯として切り出す（画面補正の数 % のずれを吸収）
2. 色で二値化して、立体的な縁取りや光沢を消す（精密採点Ai: 青背景の金・白 / Heart: 水色パネルの白）
3. 左から 5 文字分（整数 2 + 小数 3）だけを白地に黒で並べ直して、認識器にかける
4. 同じ画面の「最高点」より高い値は矛盾として扱い、小数部が一致すれば最高点に補正、しなければ空欄

### 採点画面のレイアウト（確認できたもの）
| 機種 | モード | 特徴 |
|---|---|---|
| JOYSOUND | 分析採点AI | ピンク系。内訳が数値（音程/40・安定感/30・抑揚/15・ロングトーン/10・テクニック/5）、AI ボーナス、こぶし・しゃくり・ビブラート回数、日時 |
| DAM | 精密採点Ai | 濃い青。五角形チャート（数値なし）、Ai感性ボーナス、全国平均、前回・最高、日付 |
| DAM | 精密採点Ai Heart | 水色パネル。六角形チャート（聴感が追加）、ハートボーナス、月次ランキング（○位/○人中） |
| DAM | 精密採点DX-G | ピンク〜紫。ビブラートボーナス、前回・前々回。**OCR は未対応** |

DAM の全国平均は画面に出るが、JOYSOUND（分析採点AI）には出ない。
そのため機種間の点数差を「全国平均との差」で揃える方法は DAM にしか使えない。

## 構成

```
index.html              自動撮影ページ（このままの場所で GitHub Pages に公開）
poc/ocr/
  screen.py             写真からテレビ画面を探して 1600×900 に補正（OpenCV 版）
  ocr_dump.py           補正後の画像に RapidOCR を 2 つの縮尺でかけ、文字の箱を JSON に保存
  extract.py            文字の箱から機種・モードを判定し、項目を取り出して検算する
  dam_total.py          DAM の大きな総合得点を読む（目印＋色の二値化）
  evaluate.py           正解データと比べて項目ごとの正解数を出す
  contact.py            画像を並べた一覧を作る（目視確認用）
  requirements.txt
poc/collect/
  collect.js            Bing 画像検索からサムネイルを集めるブラウザ用スニペット
  decode.py             collect.js の出力（base64）を画像ファイルに戻す
```

## 使い方

### 自動撮影ページ
GitHub Pages で公開して、スマホの Safari / Chrome で開く → 「カメラを起動」→ カメラと動きセンサーを許可。
手元で試すなら `python -m http.server` で配信して `http://localhost:8000/` を開く（パソコンのカメラか「写真で試す」）。

### OCR 試作
```bash
cd poc/ocr
pip install -r requirements.txt
# imgs/ に採点画面の写真（*.jpg）、gt.json に正解データを置く（どちらもリポジトリ外）
python screen.py imgs warped          # 画面を検出して warped/ に補正画像（dbg_*.jpg は検出結果の確認用）
python ocr_dump.py warped boxes.json  # OCR（CPU で 1 枚 2 秒ほど）
python extract.py boxes.json result.json
python evaluate.py result.json        # 正解データとの比較
python dam_total.py                   # DAM の総合得点だけを単独で試す
```

`gt.json` の形式（写真のファイル名をキーにする）:
```json
{
  "1000013093": {"machine": "JOYSOUND", "mode": "分析採点AI", "title": "ラフ・メイカー", "artist": "BUMP OF CHICKEN",
                 "date": "2025-10-10 14:28", "total": 93.652, "pitch": 33.889, "stability": 23.314, "dynamics": 14.056,
                 "longtone": 7.9, "technique": 4.493, "bonus": 10.0, "kobushi": 16, "shakuri": 2, "vibrato": 11},
  "1000012186": {"machine": "DAM", "mode": "精密採点Ai", "date": "2025-07-01", "total": 91.334,
                 "national_avg": 87.022, "bonus": 2.864, "prev": null, "best": 91.334}
}
```

## わかっていること・設計メモ

- **手ブレが最大の敵**。実際の写真で日付とボーナスが読めなかったのはブレのせい。撮影時に弾くのが一番効く（→ 自動撮影ページ）
- **2 通りの読みが一致したら採用、割れたら VLM に回す**、が確信度の目安として使える。
  精密採点Ai Heart は最高点が「---」で検算できないので、特に必要
- **連写した数枚を OCR して項目ごとに多数決**を取れば、さらに精度と確信度が上がるはず（未実装）
- 普通の OCR は、派手な画面の小さい文字は読めるが、装飾付きの大きな数字は苦手。色で二値化すると読める
- 画面の検出は、壁が明るい部屋・大きく傾いた写真で少しずれることがある。アプリでは四隅を指で微調整できるようにするのが現実的
